Ranking transactions by risk

Three Spark MLlib models were trained on January to September and tested on October to December. Accuracy is useless here because 99.47% of transactions are genuine, so each model is judged by how much fraud lands in a small review queue.

Where Docker fits

Hadoop, Hive, Spark, HBase and Pig are normally installed across a cluster of servers. The course packages them as Docker containers described in one docker-compose.yml, so a laptop can run the whole stack with one command. Each tool is a separate container, and Compose puts them on a shared network so they find each other by name, such as namenode.

Running it in your Docker environment

Run these from the folder holding the supplied compose file. Hive and HDFS need the core profile. Spark, Jupyter, HBase and Pig need the full profile.

  1. Start the containers and check they are up 
    docker compose --profile full up -d      # or the profile flag your trainer gave you
docker ps                                # every service should show "Up"
  2. Copy the data in and load it into HDFS 
    docker cp transactions.csv namenode:/tmp/
docker exec -it namenode bash
hdfs dfs -mkdir -p /data/fraud/raw /data/fraud/processed /data/fraud/results
hdfs dfs -put /tmp/transactions.csv /data/fraud/raw/
hdfs dfs -ls -h /data/fraud/raw/
  3. Create the Hive table and run the eight queries 
    docker cp hive/. hiveserver2:/tmp/hive/
docker exec -it hiveserver2 beeline -u jdbc:hive2://localhost:10000 -f /tmp/hive/02_create_tables.sql
docker exec -it hiveserver2 beeline -u jdbc:hive2://localhost:10000 -f /tmp/hive/03_analysis_queries.sql
  4. Run the Spark pipeline on the cluster 
    docker cp spark/fraud_analysis.py spark-master:/tmp/
docker exec -it spark-master spark-submit --master yarn /tmp/fraud_analysis.py \
  hdfs://namenode:8020/data/fraud/raw/transactions.csv \
  hdfs://namenode:8020/data/fraud/results
  5. Capture evidence for the evaluation
